# 2. FINAL PROJECT OBJECTIVE

Build a research-grade but locally runnable deep-learning system that accepts a musculoskeletal radiograph and can support the following outputs when corresponding verified labels exist:

1. **Binary classification**
   - class 0 / class 1 according to the verified dataset definition.
   - Do not assume class semantics until Phase 2 verifies them.

2. **Tumour subtype classification**
   - enabled only for images with verified subtype labels.

3. **Lesion localization**
   - probability/attention map for all images;
   - segmentation mask or bounding box when manual ground-truth annotations are available.

4. **Radiographic concept prediction**
   - only for manually verified concept labels.

5. **Open-set/unknown handling**
   - reject unsupported or out-of-distribution subtype predictions instead of forcing every case into a known class.

6. **Uncertainty**
   - calibrated confidence and conformal prediction sets.

7. **Explainability**
   - lesion mask/attention overlay,
   - Grad-CAM/Grad-CAM++,
   - spatially grounded concept maps when concept annotations exist.

The tool is a **research/decision-support prototype**, not an autonomous clinical diagnosis system.

# 3. NOVEL MODEL TO BUILD

## 3.1 Model name

**HOSP-BoneNet**

Expanded name:

**Hierarchical Open-Set and Spatially Grounded Bone-Tumour Network**

## 3.2 Core idea

Instead of training only a black-box image classifier, use a shared radiograph encoder and multiple supervised/partially supervised branches:

```text
Input X-ray
    |
    v
Shared pretrained visual encoder
    |
    +--------------------+
    |                    |
    v                    v
Global feature path   Lesion localization path
    |                    |
    |                    v
    |                Lesion map
    |                    |
    +---------+----------+
              |
              v
       Mask-weighted local
          feature pooling
              |
       +------+------+
       |             |
       v             v
 Concept branch   Feature fusion
       |             |
       +------+------+ 
              |
              v
      Hierarchical heads
              |
   +----------+-----------+
   |          |           |
 Binary    Subtype     Optional risk
              |
              v
      Open-set energy score
              |
              v
      Conformal calibration
              |
              v
Prediction + uncertainty + localization overlay
```

## 3.3 Backbone

Default:

```text
ConvNeXt-Tiny pretrained weights
```

Load through `timm`.

Reason:

- strong modern visual encoder,
- efficient enough for an RTX 4070-class GPU,
- exposes multi-stage features,
- useful as both a strong baseline and backbone,
- permits a controlled comparison between plain ConvNeXt and the proposed multi-branch architecture.

Allow a configuration switch to another backbone, but **do not turn backbone search into the main project**.

## 3.4 Lesion branch

Implement a lightweight feature-pyramid segmentation/localization head.

Inputs:

- intermediate encoder feature maps.

Outputs:

```text
lesion_logits: [B, 1, H, W]
```

Training:

- If mask annotation exists: Dice + BCE/Focal segmentation loss.
- If only bounding box exists: convert box to a weak spatial target or use box-supervised loss.
- If no localization annotation exists: classification-guided consistency/attention regularization only.
- Never treat Grad-CAM as a ground-truth segmentation mask.

## 3.5 Global-local fusion

Create:

```text
global_features = GeM/AdaptiveAvgPool(full feature map)
local_features  = mask-weighted pooling(feature map, lesion_probability)
```

Then use a learned gated fusion:

```text
fused = gate * local_features + (1 - gate) * global_features
```

Concatenate concept features when available.

## 3.6 Hierarchical outputs

Minimum output:

```text
binary_logits
```

Optional outputs activated only when verified labels exist:

```text
subtype_logits
risk_logits
concept_logits
```

Every task must support `unknown` or missing labels through a **masked loss** so that partially annotated images can still be used.

## 3.7 Spatially grounded concept branch

Candidate concepts:

```text
lytic
sclerotic
mixed
cortical_destruction
periosteal_reaction
soft_tissue_component
matrix_mineralization
wide_zone_of_transition
```

Do not create these labels automatically from filenames.

Concept branch design:

```text
encoder feature map
    -> per-concept 1x1 activation maps
    -> spatial pooling
    -> concept probabilities
```

Use a spatial alignment loss when lesion masks/regions are available:

```text
penalize concept activation outside the annotated relevant lesion region
```

Missing concept labels must be ignored in the loss.

## 3.8 Open-set recognition

For subtype classification:

- compute energy score from logits,
- calibrate threshold using validation/calibration data,
- support “unknown/unsupported subtype” output.

Implement leave-one-subtype-out evaluation only after enough subtype classes and samples exist.

## 3.9 Conformal prediction

Create an internal calibration split from the training set after duplicate grouping, for example:

```text
official train
    -> fit_train
    -> calibration
```

Keep official validation and test partitions untouched.

For binary prediction, conformal calibration is optional. For subtype prediction, output a prediction set, e.g.:

```text
{osteosarcoma, ewing_sarcoma}
```

when uncertainty is too high for a single subtype.

## 3.10 Loss function

Implement a configurable total loss:

```text
L =
  w_binary   * L_binary
+ w_subtype  * L_subtype
+ w_seg      * L_segmentation
+ w_concept  * L_concept
+ w_ground   * L_spatial_grounding
+ w_hier     * L_hierarchy_consistency
```

Every auxiliary term must be disabled automatically if its labels are unavailable.

# 4. COMPARISON MODELS

The main project should implement **one novel model** and use existing models only as standardized comparison baselines.

Train/fine-tune four baseline classifiers:

1. **DenseNet121**
2. **EfficientNet-B3**
3. **ConvNeXt-Tiny**
4. **Swin-Tiny**

Load pretrained weights using `timm` where possible.

Why these four:

- DenseNet is a strong conventional medical-radiograph baseline.
- EfficientNet-B3 has been used in published primary bone-tumour radiograph classification work.
- ConvNeXt-Tiny gives a modern CNN comparison and isolates the gain from HOSP-BoneNet over a plain version of its backbone.
- Swin-Tiny provides a transformer-based comparison.

All baselines must use:

- the same verified split,
- the same input preprocessing,
- the same label mapping,
- the same training budget where reasonable,
- the same evaluation code.

Do not selectively tune only one baseline to make the proposed model look better.

### Optional localization comparison

Only if reliable masks are available:

- U-Net++ or YOLOv8-seg may be trained as a localization-only reference.

This is optional and must not delay the core four-model classification comparison.

```text

## 8.2 Dataset indexing

```

Missing labels must use `NaN`/empty values, not guessed values.

## 8.3 Canonical source ID

Because filenames may contain Roboflow-style suffixes:

```text
original_name.rf.<hash>.jpg
```

derive a canonical ID that removes augmentation/export suffixes.

Also compare perceptual hashes.

This is used to detect:

- exact duplicates,
- augmented copies,
- near-duplicates,
- possible train/val/test leakage.

Do not automatically delete near-duplicates. Create a report and exclude only after deterministic rules are applied and logged.

## 8.4 Split integrity

Existing train/val/test directories are the starting split.

Before training:

- check exact hash overlap,
- check perceptual-hash overlap,
- check canonical base-name overlap.

If duplicates cross splits, create a corrected manifest-based split without moving source files.

Do not use test data for:

- preprocessing decisions based on labels,
- hyperparameter tuning,
- threshold selection,
- conformal calibration,
- early stopping.

## 8.5 Internal calibration split

From official training data, create:

```text
fit_train
calibration
```

Group by canonical source/patient/lesion ID where possible.

If reliable patient IDs are unavailable, use the strongest grouping identifier available and document the limitation.

## 8.6 Preprocessing

Default pipeline:

1. read image safely;
2. remove alpha channel if present;
3. convert to grayscale internally if appropriate;
4. replicate to three channels for pretrained RGB encoders;
5. robust percentile clipping only if validated;
6. preserve aspect ratio;
7. pad to square;
8. resize to configured resolution;
9. normalize using pretrained-backbone statistics unless an experiment explicitly tests another normalization.

Do not permanently alter original images.

Default training input:

```text
384 x 384
```

Move to:

```text
512 x 512
```

only if memory permits and validation demonstrates benefit.

## 8.7 Augmentation

Use radiograph-safe transforms:

- small rotation, e.g. ±7 degrees;
- small translation/scale;
- mild brightness/contrast;
- mild gamma;
- low-level Gaussian noise;
- optional CLAHE as an ablation, not automatically;
- random resized crop only when it does not remove the lesion.

Avoid:

- vertical flip,
- extreme perspective distortion,
- strong color augmentation,
- large rotations,
- transformations that change anatomy unnaturally.

Horizontal flip should be disabled by default because laterality markers and anatomical side may matter.

## 8.8 Filename leakage

Never feed:

- filename,
- source path,
- diagnostic keyword contained in filename,

into the model.

A filename like:

```text
fibula_osteosarcoma_16...
```

must not make the label accessible to the model.

- inspect class weights;
- sampling;
- labels;
- augmentation;
- learning rate;
- loss.

# 25. TECHNICAL BASIS USED FOR THIS DESIGN

The project design is consistent with current primary bone-tumour radiograph work and modern medical-image tooling:

- The BTXRD data descriptor demonstrates that primary bone-tumour radiographs can support classification, localization, and segmentation when labels, bounding boxes, and masks are available.
- Published multicentre work has used EfficientNet-B3 with radiographs and clinical features for primary bone-tumour histological classification, making it a relevant comparison baseline.
- `timm` provides pretrained implementations of DenseNet, EfficientNet, ConvNeXt, Swin, and many other visual backbones.
- MONAI provides PyTorch-compatible medical-imaging transforms, training/evaluation components, and metrics.
- The shared validation sample currently supports verified binary classification only; additional tasks must therefore use labels found in the full dataset or annotations created during this project.

If a package API has changed by implementation time, consult the current official package documentation rather than copying an outdated code snippet.
